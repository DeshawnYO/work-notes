# 工作笔记 V2.2 产品设计与验收

日期：2026-10-12。当前版本：2.2.0-beta.2，数据结构版本 4。本文件描述本轮实际开发范围；试用包与验证边界见 [公开交付说明](../../releases/V2.2/交付说明.md)。保留 V2.1 的编辑风，不重新改全站配色。

## 1. 已确认需求

1. 删除左侧底部的收起导航功能，以及左侧和页脚的本机保存标识。
2. 删除桌面系统标题栏下方重复的“工作笔记”菜单横条；左侧品牌图标使用软件现有 icon。
3. 报告生成前由用户指定开始、结束日期，不自动选时间；取消后台自动生成周报/月报。
4. 设置提供模型设置、模板设置两个独立分页，保留数据设置；集中管理周报、月报、项目档案模板。
5. 默认周报按项目组织功能开发及优化、项目协同；无内容保留结构、标暂无进展，事项以分号结束。
6. 默认月报按项目组织成果、进展、风险、下月计划。自定义模板优先，不改写已保存报告。
7. 报告汇总选定时间范围的工作记录、每日事项及进度，项目基础信息与档案作为必要上下文。
8. 项目管理常规界面保留左侧项目列表、右侧项目档案；支持删除项目、删除档案、上传、粘贴、编辑与一键 AI 生成。
9. 档案为空时全量检查文件；已有档案时只提取最近 7 天更新文件正文，不读取旧文件正文来重复消耗模型。
10. 保存档案不以模板存在或标题匹配为前提；正式档案使用项目目录下的 Markdown。

## 2. 页面和主流程

### 工作报告

```text
工作报告                               [生成周报] [生成月报]
报告列表 → 阅读正文 → 编辑并保存 → 下载 Markdown / Word

生成弹窗
开始日期 [用户填写]   结束日期 [用户填写]
生成方式 [AI 提炼 / 事实底稿]
[核对范围与来源]
  显示实际日期、各类记录数量、模板来源、模型和发送边界
[取消] [确认生成]
```

日期包含两端，后端以结束日次日为查询上界。日期未填写、结束早于开始、结束晚于今天均拒绝生成。每次重新打开弹窗日期为空。用户可自主选择范围，不强制固定 7 天或自然月。当前实现一次最多 366 天，是读取与模型消耗保护，非业务周期定义。

生成方式由用户明确选择。未配置模型时可选事实底稿；该方式不宣称应用自定义模板。自定义模板需要 AI 提炼来执行。先核对再生成，确认前不发送资料、不创建报告。生成中阻止重复点击和退出；错误保留时间输入。原报告有未保存修改时先处理修改。

### 设置

```text
设置
[模型设置] [模板设置] [数据设置]

模板设置： [周报模板] [月报模板] [项目档案模板]
配置范围：全局；项目档案还可指定项目
自定义模板编辑区
[上传模板] [采用默认] [恢复默认/继承] [重新读取] [保存]
[查看当前生效模板]
```

周报/月报使用全局模板。档案模板优先级：项目自定义 → 原项目模板 → 全局自定义 → 系统默认。历史项目模板保留，显式清空并保存后恢复继承。模板为空是正常配置，保存无需模型。模板变动只影响后续生成；离开、切换模板或配置范围时保护未保存输入。模板保存使用摘要检查并发变动。

### 项目管理

```text
项目列表 | 项目名称、目录              [项目信息] [删除项目]
         | [编辑/粘贴] [上传档案] [一键生成] [删除档案]
         | 档案正文 / Markdown 编辑区
         | [取消] [保存档案]
```

上传 Markdown、TXT、DOCX、有文字的 PDF 后进入编辑区，用户核对后保存，不自动调用 AI。粘贴和编辑完整正文，无模板标题限制。保存先检查版本，再保留历史，写 `_项目档案/项目档案.md`。无标题的自由文本也可保存。

删除项目只移出项目列表，原目录、档案与历史记录保留。删除档案移除当前正式文件，将删除前内容放入历史版本，可恢复；不删除原项目材料。正在生成时阻止删除。删除后保持空状态，不由后台自动重建。

重大汇报原有 Word 保存路径定位保留：从保存结果进入实际目录查看，并提供返回档案入口；常规项目页不再提供文件管理页签。

## 3. 报告来源与真实性

| 来源 | 作用 |
|---|---|
| 工作记录 | 按用户登记的事件日期选择，提炼事实、进度和协同 |
| 待办事项及动态 | 选择范围内安排、创建、更新、完成、顺延的事项；避免混入无变化旧待办 |
| 子事项 | 随父事项补充；报告期之后新建的子事项排除，之后更新的历史完成状态标未知 |
| 历史项目事项 | 纳入周期内变动，保留状态、结果、风险信息 |
| 重要会议与汇报 | 按登记时间选择，提供主要记录与意见文字 |
| 随手想法 | 范围内临时想法只作参考，不当成执行或完成成果；已转待办和源日志去重 |
| 目标 | 作为上下文，不能直接等同成果 |
| 项目背景、目标、档案 | 补齐项目解释，不当成本期发生的工作；不扫描项目全目录生成报告 |

从事项变更记录反向撤销报告期之后的修改，避免历史报告带入后来完成的状态和进度。没有完整历史证据时明确未知。图片只保留已有文字说明，不进行视觉识别，也不推测截图内容。

读取全部匹配记录，不截取前 100 条或截断 JSON。资料分批提炼，再归并摘要；模型未压缩时停止并报错，避免循环消耗。输出区分完成、进行中和缺失信息，未知处待补充。保留生成来源快照、模板摘要、记录数量、方式和模型调用次数，历史报告不伪造来源信息。

默认周报检查项目名称、顺序、两个章节和编号分号；默认月报检查项目和四个章节。AI 输出不完整时不保存假成功。自定义报告模板不强制默认章节，但不能遗漏提供的项目。事实底稿与 AI 结果都可继续人工编辑，导出只使用已保存正文。

## 4. 档案生成与 token 控制

- 开始前确认项目、模板来源、文件数量、可读数量与模型边界。模板示例和占位字段不算项目事实。
- 全量模式检查项目文件目录，只读取支持格式且大小允许的文件。格式不支持、过大、不可访问的材料列为未读与缺口。
- 增量模式需要遍历文件的路径与修改时间来判断范围，只有最近 7 天更新的文件提取正文并送入模型。即使旧文件从未索引，也不因“新发现”而读取旧正文。
- 目录自身的 `_项目档案`、隐藏项、链接目录、临时锁文件排除，避免生成内容重复成为源材料。
- 增量以现有档案和新材料合并成完整正文，保留已有事实，单列冲突与缺口；不反复追加重复的增量区块。
- 近 7 天无更新文件时保留现有档案，不调用模型。档案为空时重新使用全量模式。
- 文件摘要分批，超长旧档案先压缩；不把“下一年度”“项目群”“三目标”占位结构当成已经存在的事实。自动生成不能自称人工整理。
- 写入前检查档案和模板是否在生成中改变。外部编辑、模板变动、模型失败均保留原文，历史版本仍存在。

“只读取近 7 天”指正文读取和模型材料范围，文件更新时间的检查不等同于全量正文提取。报告与档案依然遵守项目仅本地模型限制，不能自动切换云端。

## 5. 存储、兼容与安全

- 三类模板使用本机 SQLite 设置；新增数据迁移 4 仅增加 `report_inputs`，保留原数据。
- 项目档案和历史为项目文件，数据库备份不能替代项目文件备份。
- 正式档案仍使用现有 `_项目档案` 目录，避免旧目录迁移和关联丢失。
- 重大汇报每条记录一个 Word 的规则不变。
- 原 Host、Origin、会话 token 校验、仅本地项目限制、未保存保护、档案历史与版本冲突继续保留。
- 系统标题栏保留；打开数据目录、切换数据位置和完整退出移动到托盘菜单，避免移除重复横条后丢失功能。
